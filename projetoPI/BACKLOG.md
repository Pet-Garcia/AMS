# Backlog do projeto

Este backlog organiza a atividade em histórias priorizadas. A equipe deve revisar
os itens, estimá-los e atualizar o status durante as reuniões e sprints; o arquivo
por si só não comprova a realização dessas práticas.

## Sprint 1 — Cadastro e matrícula

- [x] Como visitante, quero criar uma conta e entrar para acessar as funções do site.
- [x] Como aluno autenticado, quero consultar os cursos disponíveis.
- [x] Como aluno autenticado, quero me matricular em um curso e receber um extrato.

## Sprint 2 — Consulta e validação

- [x] Como aluno, quero consultar meus extratos e imprimir o comprovante.
- [x] Como usuário, quero consultar os alunos matriculados e filtrar por curso.
- [ ] Como equipe, quero validar o fluxo com usuários e registrar os resultados e ajustes.

## Critérios de aceite

- Uma matrícula deve associar o usuário autenticado a um curso existente.
- O mesmo usuário não pode se matricular duas vezes no mesmo curso.
- O extrato deve mostrar os dados do aluno, do curso e a data da matrícula.
- A listagem deve apresentar os alunos por curso sem expor CPF ou telefone.
- Páginas de matrícula e extrato devem exigir autenticação.

## Evidências para a entrega

Registrem no repositório ou na apresentação as pessoas envolvidas, as datas das
sprints, as estimativas, o que foi concluído e os resultados das revisões. Essas
informações dependem do trabalho real da equipe e não são preenchidas por este
backlog.
